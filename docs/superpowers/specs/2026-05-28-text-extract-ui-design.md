# テキスト抽出 UI 設計書

作成日: 2026-05-28

---

## 概要

会議文字起こし・メール文面・チャットコメントを貼り付けると、LangGraph パイプラインがタスク候補を自動抽出し、確認・編集してから起票できる UI を追加する。

---

## 配置

`/tasks`（タスク一覧ページ）のヘッダーに「テキストから作成」ボタンを追加する。クリックで横幅 1000px のスプリットパネルモーダルが開く。

---

## モーダル構成

```
┌─────────────────────────────────────────────────┐
│  テキストからタスクを抽出                     [×] │
├────────────────────┬────────────────────────────┤
│  【左パネル】      │  【右パネル】               │
│  入力元: [選択]    │  抽出結果 (0件)             │
│                    │                             │
│  ┌──────────────┐  │  タスク候補カード一覧       │
│  │  テキスト    │  │                             │
│  │  エリア      │  │                             │
│  └──────────────┘  │                             │
│  [抽出する]        │  [選択した X 件を起票]      │
└────────────────────┴────────────────────────────┘
```

### 左パネル

- **入力元セレクター**: ラジオボタン 3 択
  - `email` → メール
  - `meeting` → 会議文字起こし
  - `chat` → チャット
- **テキストエリア**: 最低 12 行・リサイズ可能
- **「抽出する」ボタン**: テキスト未入力時はバリデーションエラー、入力済みで `POST /api/v1/tasks/extract` を呼び出す

### 右パネル

抽出結果のカード一覧を表示する。

```
┌─────────────────────────────────────────────────┐
│ ☑  採用稟議書の作成                    [編集]   │
│    担当: 田中太郎  期日: 2026-06-10  優先: 中   │
│    信頼度: ████░░  78%                          │
├─────────────────────────────────────────────────┤
│    （グレー）会議室の予約確認          [昇格]   │
│    担当: 未設定    期日: 未設定      優先: 低    │
│    信頼度: ██░░░░  30%                          │
└─────────────────────────────────────────────────┘
```

- **チェックボックス**: 起票対象の選択。デフォルトで `is_task: true` の候補が選択済み
- **グレーアウト行** (`is_task: false`): 「昇格」ボタンで `is_task: true` に変更してチェックボックスを有効化
- **信頼度バー**: `confidence_score` を Progress コンポーネントで表示
- **「編集」ボタン**: サブモーダルを開き以下を編集可能
  - タイトル（必須）
  - 担当者（`useUsers` フックで取得したユーザー一覧から Select で選択）
    - LLM が `assignee_name` を抽出した場合、Select のラベル横に「🤖 AI提案: {assignee_name}」をヒント表示する
    - ユーザー一覧の Select は `assignee_name` でフィルタした状態で初期表示（例: 「田中」→「田中太郎」が候補に絞られた状態）
    - ユーザーが Select で確定するまで起票時の担当者には反映されない
  - 期日（DatePicker）
  - 優先度（high / medium / low）
  - プロジェクト（プロジェクト選択）
- **「選択した X 件を起票」ボタン**: 選択済みカードを順次 `POST /api/v1/tasks` で起票

---

## データフロー

```
1. ユーザーが入力元を選択してテキストを貼り付ける
2. 「抽出する」クリック → POST /api/v1/tasks/extract { text, source_type }
3. 右パネルに ExtractedTask[] を表示
4. ユーザーが各候補を確認・編集・選択
5. 「起票」クリック → 選択候補を順次 POST /api/v1/tasks
6. 全件成功でモーダルを閉じてタスク一覧をリフレッシュ
```

---

## 機密テキスト（Pattern B）検知

バックエンドが機密判定した場合、`tasks` が空配列かつ `skipped_reason` が含まれるレスポンスが返る。フロント側では抽出ボタン押下前に**警告バナー**を表示して確認を求める（判定はサーバー側が最終）。

```
⚠️ 機密データが検知されました
このテキストには社外秘キーワードが含まれています。
外部 LLM には送信されません。
                          [キャンセル] [それでも送信]
```

「それでも送信」を押した場合も、サーバーが Pattern B と判定すれば結果は 0 件になる。

---

## エラー処理

| ケース | 表示 |
|--------|------|
| テキスト未入力 | 入力欄のバリデーションエラー（赤枠） |
| LLM API エラー（503 等） | 右パネルに Alert「抽出に失敗しました。再試行してください。」 |
| 抽出結果 0 件（Pattern B 以外） | 右パネルに「タスクが見つかりませんでした。」 |
| 起票失敗（個別） | 該当カードに赤枠 + エラーメッセージ |

## 備考

- バックエンドの `ExtractedTask.source_id` は必須フィールドだが、UI からは設定しない。起票時（`POST /api/v1/tasks`）は `TaskCreate` モデルを使用するため `source_id` は不要。抽出結果はフロントエンドのローカル状態として保持し、DB には起票確定後のみ書き込む。

---

## 非機能要件

- TypeScript strict モード準拠
- 抽出中・起票中はローディングスピナーを表示してボタンを無効化
- モーダルを閉じるとテキスト・結果をリセット
- 既存の `useCreateTask` フックを使って起票（タスク一覧と同じ invalidate を実行）
