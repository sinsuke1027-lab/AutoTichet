## グループ A：プロジェクトメンバー基盤（#10）

### DB

**Alembic 0009**: `project_members` テーブル新設

```sql
CREATE TABLE project_members (
  project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  user_id    TEXT NOT NULL,
  role       TEXT NOT NULL DEFAULT 'member',  -- 'owner' | 'member'
  joined_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (project_id, user_id)
);
```

### バックエンド

**新規 Pydantic モデル** (`task_web.py`):
- `ProjectMemberAdd(user_id: str, role: str = "member")`
- `ProjectMemberResponse(user_id: str, role: str, display_name: str | None, joined_at: datetime)`

**新規エンドポイント** (`projects.py`):
- `GET  /api/v1/projects/{id}/members` → `list[ProjectMemberResponse]`（全認証済みユーザーが参照可）
- `POST /api/v1/projects/{id}/members` → 201（権限: `role=owner` のメンバー or admin のみ）
- `DELETE /api/v1/projects/{id}/members/{user_id}` → 204（権限: `role=owner` のメンバー or admin のみ）

**ロールの意味**:
- `owner`：プロジェクト作成者。メンバー追加・削除・プロジェクト編集が可能
- `member`：招待されたメンバー。タスクの閲覧・操作のみ可能（メンバー管理は不可）

**`ProjectCreate` モデル拡張**:
- `member_ids: list[str] = []` を追加
- `POST /api/v1/projects` でプロジェクト作成時に `project_members` を一括 INSERT（作成者は `role=owner` で自動追加）

### フロントエンド

**Zustand ストア** (`useProjectStore.ts` 新規):
```ts
interface ProjectStore {
  activeProjectIds: string[]      // 選択中プロジェクト（空 = 全プロジェクト）
  activeDeptTag:   string | null  // 現在の部門コンテキスト（自動セット）
  setActiveProjects: (ids: string[]) => void
  setActiveDeptTag:  (tag: string | null) => void
}
```
localStorage に永続化（`persist` ミドルウェア）。

**サイドバー上部 UI** (`App.tsx` / `Sidebar.tsx`):
```
┌─────────────────────────────┐
│ 所属部門: [人事部]  ← 兼任時のみ切り替え可（Select）
│ プロジェクト: [全て ▼]      ← 複数選択 Select（自分が属するもの）
└─────────────────────────────┘
 ダッシュボード
 タスク一覧
 ...
```

- 部門タグはログインユーザーの `department_tags` から自動セット。**1件のみの場合は Select を disabled 表示**、2件以上（兼任）の場合のみ切り替え可能
- プロジェクト選択は `useProjects({ scope: 'mine' })` から取得（自分が `project_members` に含まれるもののみ）
- `activeProjectIds` が変わると各ページの TanStack Query が自動的に再フェッチ

**各ページへの注入**:
- `useTasks` / `useTasksForView` / `useWorkload` など主要フックが `useProjectStore` を参照し `project_id` を自動付与

### #12 カンバン楽観的更新

`Board/index.tsx` の `useUpdateTask` 呼び出しを `onMutate` パターンに変更:
```ts
onMutate: async ({ taskId, status }) => {
  await queryClient.cancelQueries({ queryKey: ['tasks'] })
  const previous = queryClient.getQueryData(['tasks'])
  queryClient.setQueryData(['tasks'], (old: Task[]) =>
    old.map((t) => t.id === taskId ? { ...t, status } : t)
  )
  return { previous }
},
onError: (_err, _vars, ctx) => {
  queryClient.setQueryData(['tasks'], ctx?.previous)
},
onSettled: () => queryClient.invalidateQueries({ queryKey: ['tasks'] }),
```

## グループ E：公開範囲拡張（#9）

### DB

**Alembic 0010**: `tasks` テーブルに 2 列追加

```sql
ALTER TABLE tasks ADD COLUMN visibility_tag        TEXT    DEFAULT NULL;
ALTER TABLE tasks ADD COLUMN visibility_project_id UUID    DEFAULT NULL
  REFERENCES projects(id) ON DELETE SET NULL;
```

既存の `visibility` は `private | team | all` を保持し、新値 `tag` / `project` を追加:
- `visibility = 'tag'`     → `visibility_tag` が有効
- `visibility = 'project'` → `visibility_project_id` が有効

### バックエンド

`TaskCreate` / `TaskUpdate` に追加:
```python
visibility_tag:        str | None = None
visibility_project_id: uuid.UUID | None = None
```

`_scope_condition` の拡張: `visibility = 'tag'` の場合 `current_user.department_tags` に含まれるかチェック、`visibility = 'project'` の場合 `project_members` でメンバーシップチェック。

### フロントエンド

タスク作成モーダルの公開範囲 Select を拡張:
```
個人 / チーム共有 / 全員 / ── / 特定タグ → タグ Select 展開 / 特定プロジェクト → プロジェクト Select 展開
```
`visibility` が `tag` or `project` を選んだとき、追加の Select を条件付き表示（`Form.useWatch`）。
